# v10 operator and recovery guide

Keep the existing sibling Main and Operation Hunter folder names. Follow README.md for dependencies, configuration, database backup and suite startup. Use Node 22.13+ or Node 24, Python 3 and Chromium. Actual runtime and platform certification limits are in the release report. Existing state upgrades are additive through migrations 0021/0022; preserve complete pre-upgrade backups.

## Investigation
Click Start Investigation. Its durable request identity survives normal reloads, lost responses and scheduler restarts. A denied browser storage permission still preserves the identity for retries in the current page; reload recovery in that case is limited to the server dashboard. If Finder has no sufficiently supported candidate within its bounded allowance, Main parks the search with its reason. The supplied URL path remains under Investigate This Site.

Routine public collection, passive wallet ingestion, validation, bounded chain analysis and report preparation remain automatic. A root mission permits four sites including itself, at most two levels deep, and shared ordinary-job/network allowances. Related sites retain separate investigations, evidence, reports and approvals. Open the mission view to inspect remaining allowances and uncertainty. Generic infrastructure, copied pages and transaction counterparties never prove ownership.

When Main needs normal authentication, open the site and perform it yourself. In Logger options open Private Account Workspace, explicitly prepare a legitimate new account or import an account you own, choose the matching top-level HTTPS tab and explicitly fill login, signup or verification fields. Fill never submits. Complete the site's normal actions yourself. Mailbox creation/recovery is tied to the saved account identity; polling and response size are bounded. Verification links open only when you choose them. Reveal/copy is explicit. A master password of at least 12 characters protects the complete payload. The vault locks after inactivity or worker restart; existing-vault capture pauses until explicit unlock. Secrets stay out of evidence/export/sync. Unsupported legacy vault formats fail closed and preserve their source.

When Main displays Report ready. Submit?, review its evidence and destination, then Approve & Submit. Approval binds the exact report hash. An uncertain submission response is retained as uncertain; it must not automatically create another logical submission. Main never signs wallet transactions or requests seed phrases/private keys.

## Recovery checkpoints
A recovery ZIP contains both sibling source folders, public verification artifacts and V10_SOURCE_MANIFEST.json. Verify the ZIP SHA-256 against its checkpoint receipt, check every manifest file hash, and extract into a fresh directory. Reuse the original configuration and complete data only after preserving backups. Dependencies, private configuration, secrets, runtime databases and browser profiles are deliberately absent. Git commit identifiers in a manifest document their original run; the ZIP itself does not include Git history.

The execution workspace reverted during this release. Checkpoint 12 restored all 1,487 recorded files exactly; unarchived later edits were reapplied and retested. A packaging exclusion had omitted two required build-source files from historical archives; later checkpoints restore build/sites-vite-plugin.ts and its license. Checkpoint 13 onward includes them. A later rollback was recovered from checkpoint 18 with all 1,540 manifest files verified. The live checkpoint ledger records subsequent reconstruction and fresh verification.

## Reproduce checks
From Main, npm test runs the portable unit list. npm run test:v10 runs the v10 authority/confidence/projection, mission, process-kill, joined and account checks. npm run test:all includes historical regressions and rendered UI. Set MIP_PYTHON to a working Python 3 interpreter when needed. Browser tests need Playwright/Chromium. ENVIRONMENT-BLOCKED and FAILED rows in the release report remain explicit; successful test execution does not certify a failing scientific quality target.
