# V8 Scientific Intelligence — implementation and verification report

Date: 2026-10-03. Package: `main-investigation-platform-v10-suite-v8-scientific-intelligence.zip`.

**Release decision: implementation candidate, not a complete or fully certified v8 release.** Main now changes a bounded explanation when specialist evidence contradicts it, and retains genuinely unresolved disagreement. The contradiction-resolution count is nonzero in acceptance, the reasoning laboratory and a real specialist workflow. However, held-out decision ranking does not consistently improve over v7, full queue quiescence still fails, and several advanced capabilities are incomplete. Passing fixture assertions is not evidence of general reasoning accuracy.

## Hypotheses, predictions and test outcomes

**VERIFIED within the acceptance fixtures:** Hunter explanations become competing question sets. Linkage questions include meaningful association, shared kit/vendor, shared provider and unknown alternatives. Each persisted explanation carries its statement, role, set scope, independent supports and challenges, unexplained observations, alternatives, assumptions, bounded predictions, test families, qualitative uncertainty, status and revision reason. Scope is currently the containing operation/set, rather than an arbitrary per-hypothesis logical predicate.

States are qualitative. Distinctive reuse from independent categories can support association while leaving attribution unproven. Generic template/CDN overlap keeps generic alternatives viable. Validated different scoped deposit addresses reject an explicit unchanged-single-wallet prediction; they do not prove different owners. Rotation can remain viable alongside configuration changes, different operators and observation errors. Unknown remains legitimate.

Important tests receive a frozen three-branch plan before specialist handoff or local execution: new/changed observation, not observed within a bounded check, and inconclusive. The branches explain what each result means for each competing hypothesis and retain a prediction hash and observation baseline. Replays do not rewrite the plan after seeing results. Hypothesis and prediction creation share a transaction with their history; test plans share a transaction with reservations.

**IMPLEMENTED BUT PARTIALLY VERIFIED:** the branch descriptions are conditional analytical expectations. Outcome assessment correlates newly versioned source observations to the test's exact job, preserves checked URLs, coverage and limitations, and records a comparison. It is not a general executable prediction language. The first ordered question set is planned; selecting the globally most informative set among many unresolved questions is not implemented. Ranking extends v7's discrimination/value components with fresh-artifact and temporal replacement rules and a bounded falsification preference. A full expected separation calculation over calibrated branch probabilities is **NOT IMPLEMENTED**. Consequently, this report does not claim that discrimination is the dominant calibrated criterion for every test.

## Contradictions and negative evidence

Comparable observations conflict when their subject, facet and captured time match but their values disagree. Both sources remain stored. Different captured times are preserved as potential change, rather than automatically called a conflict. Material Hunter contradictions remain active questions and are not dropped when a later Hunter snapshot omits them.

Contradictions retain the challenged claim, observations, independence units, plausible explanations, candidate test families, materiality, status, resolution references and revision history. The seven requested outcome labels are defined. The verified automatic paths are `UNRESOLVED`, `EVIDENCE_ERROR` after an explicit deterministic scoped correction, and `RESOLVED_WEAKENS_HYPOTHESIS` after a false bounded wallet prediction is contradicted. An evidence-backed Hunter resolution can produce `RESOLVED_ALTERNATIVE_EXPLANATION`. The existence of every label is not certification of every transition: automatic support resolution and split-required adjudication remain incomplete.

Provider disagreement is shown as source-specific assertions, followed by Main's inability to resolve it. No majority vote or manufactured consensus is used. A deterministic correction must explicitly identify the erroneous evidence; merely having a more authoritative-looking source is insufficient. The correction path has an authenticated ingestion acceptance test but is not demonstrated through a new live provider correction adapter.

**VERIFIED negative-evidence discipline:** unsuccessful or partial checks cannot establish absence. Even successful Internet searches cannot establish global absence. The pure semantic function permits absence only inside an explicitly finite, fully covered, successful scope with no limiting conditions. Current production public-search assessment conservatively records failure to observe, because its limitations include incomplete public coverage. Unavailable results remain inconclusive. Analyst-facing predictions and software learning never become source evidence.

## Reliability, independence and commonality

Six categorical reliability types remain distinct: direct observation, deterministic validation, provider-returned data, derived software analysis, external metadata and analyst conclusion. Wallet Investigator supplies address-validation authority; Logger supplies the original presentation observation. Validated-deposit projections retain the original evidence ID, candidate, validation job and actual observed domain. They are scoped to that deployment, not every site belonging to the same investigation.

Explicit upstream origins collapse copied records to one unit. Distinctive wallet reuse and distinctive public contact reuse can contribute different units. Relationship-derived reuse retains its source evidence IDs and relationship provenance. Where sources omit upstream origins, perfect copy detection is unavailable; categorical source reliability does not make copied records independent.

Corpus frequency is an observation about the stored corpus, not the whole Internet. Template, hosting and blockchain relationship categories are conservatively generic; frequently observed targets are discounted. No shared CDN, template, hosting or counterparty produces automatic ownership or consolidation. Counterparty relationship discounting is implemented, but a service-specific calibrated exchange/commonality estimator is **NOT IMPLEMENTED**. Generic overlap can reflect benign shared infrastructure; no generated ownership claim is written.

## Alternatives, fresh branches, replacements and boundaries

The v7 template-variant/infrastructure tests provide bounded alternative-explanation searches. v8 reserves a configurable fraction (default 0.25, clamped to 0–0.5) of the existing operation allowance for template/infrastructure/contradiction tests. This never extends total budgets; urgent report and time-sensitivity thresholds precede this preference. It is a heuristic allocation of test units, not a separately metered monetary account. Long-run fulfillment of that fraction, and urgent behavior below the current threshold, remain partially verified.

Branch records persist input novelty, previous useful discoveries, duplicate rate, attempt depth, last useful result, bounded coverage and unexplored artifacts. Previously empty seed hunts no longer automatically exhaust a fresh distinctive artifact branch. Freshness partly means unsent inputs, not a measured creation date for every artifact. Depth is currently branch attempt history, not a universal graph-hop metric.

Replacement ranking uses recorded disappearance, changed-status age, continuity artifacts and prior branch exhaustion. It preserves temporal uncertainty. **NOT IMPLEMENTED:** a fitted historical replacement-cadence model and an explicit causal chronology/deployment-wave inference model. Existing v6 temporal facets and v7 wave candidates remain available. Temporal proximity alone never establishes replacement or control.

Scientific split proposals use different validated deposit/contact clusters and require analyst review through v6's existing hashed decision mechanism. They include both clusters' evidence, generic shared evidence, reasons and uncertainty. Proposal alone mutates no boundary. The rule is deliberately conservative and currently blocks a split whenever distinctive reuse remains anywhere in scope; it can miss legitimate splits with internal cluster reuse. Automatic cluster discovery from arbitrary evidence and independently certified split correctness are incomplete. Analyst-approved merge/consolidation semantics and source history remain unchanged.

Saturation uses v7's existing marginal value, exhaustion, budgets and wake conditions. Scientific sets record `BEST_SUPPORTED_BUT_UNPROVEN`, `ALTERNATIVES_REMAIN`, `INSUFFICIENT_EVIDENCE` or `CONTRADICTORY_EVIDENCE`; these are descriptions of understanding, not claims of certainty or proof that every alternative was exhaustively tested.

## Decision learning v2

Existing causal outcome learning, actual-cost ledger, portfolio scheduling, dynamic budgets and parking/wake remain in use. Scientific comparison credits `hypothesis_discriminated` and `contradiction_resolved` only when a new observation has exact job lineage and its evidence ID participates in the revision. Comparison, history and scientific credits commit together. Versioned observation baselines allow changed records, rather than treating an existing ID as permanently unchanged. Family statistics recognize the two new outcomes alongside v7 outcomes, with bounded credit.

**IMPLEMENTED BUT PARTIALLY VERIFIED:** these credits represent evidence-backed analytical changes, not independently known truth. The real revision fixture proves the revision, not complete end-to-end learning attribution for every step. **NOT IMPLEMENTED as separate, certified v2 credits:** alternative explanation discovered, correctly split operation, generic correlation rejected, replacement found, and fresh branch produced independent evidence. Existing v7 discovery/validation/independence credits still apply. Learning remains outside evidence and report content.

The scale fixture contains 10,000 entities, 50,100 relationships, 5,000 evidence records, 300 investigations and 25 operations. It retains 10,000 v7 tests/decisions, 144,000 decision components, 100,000 cost rows and 30,000 outcomes, plus 5,100 scientific hypotheses, 5,100 predictions, 5,000 contradictions and 30,100 scientific history rows after projection. All 50,100 edges were actually projected.

**VERIFIED local measurements:** cached scientific briefing 4.03 ms; bounded Advanced view 4.72 ms; first graph/briefing page 12.91 ms. Eight-operation decision ticks measured 1,424.38–1,970.25 ms. Database size grew from 2,101,248 bytes to 175,972,352 bytes; scientific fixture/history added 11,096,064 bytes before execution, and the run added 76,304,384 bytes after loading. Peak RSS was 322,080 KiB. These are file-backed SQLite/D1-double measurements, not a remote D1 SLA. Projection/history growth remains a concern. Scientific reads are bounded (1,200 observations, 2,000 relationship rows and 200 deposit projections); the briefing cannot claim complete large-operation evidence coverage. The recorded “v6 policy” timing disables adaptive choice but leaves passive scientific projection on, so it is not a clean v6-versus-v8 overhead experiment.

Specialist consumed dimensions remain NULL when no actual meter exists. The hidden workflow separately counts synthetic transport calls, which are not retroactively inserted into production cost rows. Additional Site Investigator/Wallet Investigator/Hunter meters were not added; actual-count coverage remains incomplete.

The bounded reconciliation test examined four stale work items, resolved one with target-specific completed-job proof, retained three uncertain items, deleted none and created no duplicate event on replay. Reconciliation handles unlinked queued/deferred investigation/revisit work only; a later change invalidates the old completion proof. It preserves running work and uncertain retries. **FAILED full quiescence:** the preserved hidden A/B still ends with queued/running work but no active jobs. The new reconciliation is not a complete fix for those pre-existing items.
